# Schema changes

No breaking changes to the M0 contract.

Additive / clarifications used by later milestones:

- `referenceAudio` is required as `{ path: string, offsetMs: number }` (empty `path` = none). It is not nullable, so JSON Schema and `validateProject` stay simple.
- JSON **export** adds `exportedAt` (ISO-8601). Import strips it before validation so the core `Project` type is unchanged.
- `schemaVersion` is `1`.

## Generation

- Additive generation-stage change: **rhythm realization (Stage 6.5)** (`src/generation/rhythm.ts`) runs between the semantic score and the project track adapter, turning sustained per-beat events into role-appropriate figures (rearticulated ostinatos, phrased lead lines with breath rests, occasional mid-note rearticulation for bass/pad). No schema change. `AbstractNoteEvent` pitch fields are never modified — the realizer only splits, rearticulates, rests, or repeats existing events, so range/voice-crossing/parallel invariants are preserved.
- Module 4 additive stages: **articulation selection (Stage 7**, `src/generation/articulation.ts::selectArticulations`**)** picks per-event playing techniques from the Module 4 decision trees (strings/woodwinds/brass; percussion & keys pass through untouched), and **anti-machine-gun (Stage 8**, `applyAntiMachineGun`**)** tags chained repeated short notes with deterministic velocity/timing jitter and bow-direction alternation. Both run after rhythm realization, before the adapter bake, with dedicated RNG salts (0x4a17 / 0xb0b5; registry at the top of generate.ts). Ff brass peaks (RIP/DOIT/FALL_OFF) gain host-agnostic pitch-bend ramps stored as `Note.pitchBendPoints`.
- Schema additions (additive, optional; `schemaVersion` stays 1): `Note.technique`, `Note.bowDirection`, `Note.isKeySwitch`, `Note.pitchBendPoints`, `LibraryGroup.keySwitchMap`, `LibraryGroup.preTriggerDelayMs`. Key-switch notes are emitted **at export time only** (never stored in `track.notes`, never scheduled by playback); `validateProject` range-checks the new fields.
- Module 5 (deterministic, no new RNG/salts): **Stage 4.5 `LowIntervalLimitFilter`** repairs non-compliant intervals between adjacent voices below C3 (sub-bass C1–C2 octaves-only; mid-bass C2–C3 P4/P5/octaves) by octave-raising the upper voice, cascading on collision, and flags `VoicedHarmony.lowIntervalCompliant`. **`SEMI_OPEN` voicing** (drop 2nd voice from the top an octave) joins the voicing-style union/schema/dropdown. **`VoiceLeadingConfig`** weights/penalties (additive optional `GenerationSettings.orchestration.voiceLeadingConfig`) thread through `PipelineOptions`; defaults reproduce legacy cost magnitudes exactly. `VoiceLeadingResult` gains `transitions` audit records. Leading-tone/7th resolution is a new soft penalty; parallel-5th/octave penalty keeps doublings/unisons (OCTAVE_DOUBLING) exempt by design. No schemaVersion bump.
- Module 6 (deterministic, single RNG stream, new salt 0xd0b1): post-score **doubling + anti-flanging stage** (`src/generation/doubling.ts`) runs between AMG and the adapter bake — never inside `generateOrchestralScore`, so the six-stage contract is untouched. `applyDoublings` realizes the doubling matrix (unison hybrid timbres + octave doublings + mandatory low-flute < G4 and low-bass < C2 protection) as octave/pitch-class-preserving double events; `applyAntiFlanging` defends same-instrument unisons with deterministic detune (±5c), micro-delay (4–12ms) and CC74 jitter; heterogeneous unisons stay untouched. Optional `orchestration.doubling` config (additive; `schemaVersion` stays 1) and additive `Note.isDoubling`/`Note.cc74Offset` fields. Section-disposition router orders woodwind/brass voice assignment (chair-level schemes deferred to Module 11). Playback now honors `detuneCents` so intonation/anti-flanging are audible in preview.
- Module 3.5 + Module 7: the generation adapter now consumes all 23 instrument-database profiles through `src/generation/profileAdapter.ts`, mapping DB families, roles, register bands, carrying power, blending groups, professional/practical ranges, and negated DB transposition offsets into the pipeline convention. Supplemental piano/harp profiles remain; tuba can enter the existing cinematic BASS rotation. **Generated pitches may differ slightly from previous builds** because ranges now use the instrument database's practical/professional boundaries.
- Module 7 adds deterministic, no-salt antiphonal windowing, accompaniment attenuation, register-aware CC11/CC74 dynamics and additive optional `orchestration.balance` / `Note.dynamics`. At MIDI export, CC#7 is a static per-track acoustic carrying-power fader; generated-note expression and brightness CCs use balance dynamics while manually authored notes retain legacy velocity/technique fallbacks. The dynamic CC remains velocity/127 and track-specific expression CC assignments remain honored. Schema version remains 1.
- Polyphony hotfix (winds/brass): **occupancy ledger** in `applyDoublings` — every double insertion checks the receiver's per-instrument calendar (self line wins; ≤1 doubling source per window; window padded ×1.02 for the legato duration multiplier); **sparse unisons** — ALWAYS-class rules require a sustained (≥1 beat) or fortissimo (≥0.85) primary AND pass a seeded 35% gate drawn from the same 0xd0b1 stream; **pad-completion scatter** — uncovered chord tones rotate round-robin across pad instruments (string profiles cap at 2, overflow goes to keyboard profiles, else dropped); **MonophonyGuard** (`src/generation/monophony.ts`) — final one-note-at-a-time invariant (winds/brass 1, strings 2 double-stops, keys unlimited), legato-handoff truncation with LEAD>COUNTERLINE>OSTINATO>BASS>PAD priority, runs LAST after humanization and Module 8 gestures, expected zero resolutions. Expected sound change: winds play single lines, oboes no longer mirror flutes, bassoons stay clean through the chorus. No new salts/RNG sources; schema unchanged.
- Addendum E/F/G (additive; schemaVersion stays 1): **E theme engine** (salt 0xe551) replaces the LEAD grid with grounded germ phrases rotated across the pre-existing lead layer, per-note contour walk in the project key, chord-tone anchors nearest the line, cadence on phrase-end downbeats; **F NCT engine** (salt 0xf0c8) inserts passing (rate 1.0) > neighbor (rate 0.45) tones into thirds/tenths, neighbor tones always single steps (±1–2 semitones, never octave jumps), leap-repair steps ±1–2 only, one NOTE inserted ≥ MIDI 48 including after leap-repair, structural notes never pushed below C3; **G counterline/ostinato cell engine** (salt 0x6066) owns COUNTERLINE/OSTINATO wholesale (viola/cello/horn/clarinet register; contrary-side chord-tone entries; G.3 curated rhythm seeds; G.6 bass approach tones). Wiring order in `generate()`: E → F → G → Stage 6.5 realizeRhythm. **Phase 0 roles contract**: engines ON ⇒ realizeRhythm shapes BASS/PAD only (`roles: ["BASS","PAD"]`; roles whose engines are off stay legacy); engines OFF (all `generationSettings.themes` switches false) ⇒ no roles option = legacy path, **byte-identical** to the pre-E/F/G pipeline (golden digests: `src/fixtures/efg-legacy-golden-{6,15,42}.json`, in-app length+FNV64 test; node byte-compare script). Defaults are explicitly ON in `createDefaultProject` (`themes: { germ: true, nct: true, counterline: true }`); validation checks the flags. Monophony guard gained a deterministic pairwise-overlap post-pass (long note spanning nested sub-events can no longer exceed the cap). No new RNG salts (0xe551/0xf0c8/0x6066 were already the engine salts; Math.random remains zero in generation code).
- Module 8 (**structure mapping & density engine**, `src/generation/arrangement.ts`): deterministic macro-arranger with three touch points and NO new RNG salt. PRE-pipeline: per-measure density profiles (`Es` from section baselines × target-dynamic slider multiplier, an H_tension approximation from the existing chord parser, and a build-only transition ramp honoring additive optional `Section.buildCurveType` LINEAR/EXPONENTIAL/STEPPED) drive additive `realizeRhythm` probes (`intensityAt` / `subdivisionCapAt`; defaults byte-identical); **virtual section tiling** splits BUILD sections into exact 2-bar slices with escalating targetDynamic and ascending densityLevel fed to stage 2 (its groupFor/DENSITY_VALUES mappings untouched), plus an OUTRO decay split. POST-score: **breakdown drop** (after doubling, before attenuation/dynamics) keeps only the configured exposed layers (`generationSettings.arrangement.breakdownExposedLayer`, default SOLO_CELLO) inside Breakdown windows and truncates notes spanning the boundary. BAKE: deterministic **transition gestures** (timpani roll + accent, cymbal swell with grace crescendo) written directly onto tracks before build→chorus boundaries; the pre-boundary ascending scale run is owned by the LEAD melody engine (theme.ts), so Module 8 deliberately writes percussion only — no flute/violin scale runs, preventing double runs over each other; percussion register rules pinned (cymbals = pitch 49). Schema additions are additive optional (`Section.buildCurveType`, `generationSettings.arrangement`); schemaVersion stays 1.
- Module 8.5 (**arrangement intelligence**, `src/generation/rotation.ts`): seeded role rotation, active masks, rest budgeting and the chorus role divider. **Salt registry update**: new salt 0x8a55 (rotation casting) is the ONLY RNG in this module, spent exclusively in `planRotation`'s single `mulberry32(seed + 0x8a55)` stream; draw order is deterministic (sections in time order; layers in fixed order LEAD → BASS → PAD → COUNTERLINE → OSTINATO; one uniform draw per layer, redraw only on the rest-budget hand-off trigger). **Profiles are sections, not chairs** — pools and casts address section roles ("flutes"), never chairs ("Clarinet 1"); chair-level rotation is reserved for Module 11, which will plug chairs into the same pools. Three insertion points in `generate()`: `planRotation` pre-pipeline (projects sections via name normalization: "Verse 1" → verse, index-free casting, no Bridge type — maps to build); `applyRoleRotation` + `applyActiveMask` post-score between the cell engine and Stage 6.5 (doubles therefore attach to FINAL carriers, and articulation/dynamics see final written pitches); `divideChorusRoles` post-bake after gestures, BEFORE the guard (the guard stays last). Rotation remaps REAL melodies octave-only: group median refit into the carrier's comfortableRange + per-note `pitchInClass`, written pitch re-clamped — pitch classes survive exactly, so motif shape, cadence targets and chord alignment are preserved through hand-offs. Active masks use ONLY M8 measure profiles (no new energy math): per measure the allowed set is drawn carriers ∪ M8 breakdown exposed layer (union, never intersection in breakdown windows), then the family band (Intro/Outro strings+woodwinds+keys; verse brass only for the pad row; PreChorus/Build/Chorus unrestricted), then the `maxActiveTracks` cap by priority — drawn LEAD/BASS/PAD carriers are always kept (minimum-ensemble). Rest windows mask the exiting lead carrier for `restBars` (2–4) after its ≥ `restTriggerBars` (default 8) carry span; a section is never left leadless (pool exhaustion keeps the previous carrier). **Cameo preservation** (refinement of the cap's "then anything else in existing order" clause): a til-now-never-silent castable color that the sweep leaves with zero events score-wide reinstates its first contiguous phrase (≤ 1 bar window) at its original position, octave-refit back to ITS OWN range — deterministic, no RNG, mask still applies. Chorus lead draws from the high-register pool only; the violins1+trumpets tutti color is a doubling rule, not a second lead: `{ primaryRole: "violins1", doublingRole: "trumpets", intervalSemitones: 12, minDynamicLevel: 0.85, condition: "TUTTI_PEAK" }` appended to DEFAULT_DOUBLING_RULES (data only; ledger + sparse gates govern it). `divideChorusRoles` — within a casted section each track's non-doubling notes must share one semantic role; mixed tracks keep the majority (tie → LEAD > COUNTERLINE > OSTINATO > BASS > PAD) and drop the rest; doubling guests are exempt (they follow their source line — that IS the lead layer); expected ≈ 0 resolutions (measured 0 on the Dorian fixture across seeds 1–20). `Note.role?` (additive, rotation build only) is stamped at bake for divider input; rotation-off output stamps nothing, keeping byte-identity. **rotation-off = identity proof**: with `generationSettings.arrangement.rotation.enabled === false` (or the whole object absent AND enabled explicitly false) every 8.5 path is a no-op — no 0x8a55 draws, no stamp, no mask, no divider — and output is byte-identical to the pre-8.5 build; the E/F/G golden digests pin exactly that scoped identity. Note: with rotation enabled (the default) the audible output IS intended to change: opening lead carriers differ across seeds. Additive optional `generationSettings.arrangement.rotation` config validated when present ("rotation config" errors; integers; restBars clamped 2–4); schemaVersion stays 1. Style-preset seam (future): presets may shrink pools or override masks via the same config. No new dependencies.
